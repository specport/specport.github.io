# SpecPort GitHub Pages

This repository is the dependency-free static site published at
<https://specport.github.io/> through `.github/workflows/pages.yml`.

The page leads with the current product wedge: compare the exact final Git tree
with an approved scope or pinned review before merge. A bare `coverage` run is
described honestly as an inventory; it becomes a coverage verdict only when the
user supplies an explicit comparison source. The broader `SPEC.md` lifecycle is
secondary workflow depth, and the public spec network remains labeled future.

## Generated release and proof data

`release.json` is generated by:

```powershell
node scripts/sync-site-release.mjs
```

The script reads the sibling SpecPort package by default, checks the exact
version and tarball against npm, and fails closed when the registry cannot prove
publication.

The visible coverage example is a deterministic synthetic fixture, not customer
evidence. `proof/coverage-gap/receipt.json` is generated by the real built
SpecPort coverage engine:

```powershell
node scripts/generate-coverage-proof.mjs
```

Set `SPECPORT_SOURCE_DIR` when the package source is not available at
`../specport`. The package must be built first.

## Verify locally

```powershell
node scripts/sync-site-release.mjs
node scripts/generate-coverage-proof.mjs
node scripts/verify-site.mjs
```

Then serve the directory with any static server and inspect the first screen,
proof receipt, copy buttons, navigation, and release metadata at desktop and
mobile widths.

The Pages workflow checks out the public `specport/specport` repository at `main`, installs and builds
that trusted source checkout, regenerates release and proof data, runs the site
verifier, and uploads the static files plus the proof fixture.
