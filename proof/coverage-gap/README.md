# Coverage-gap example

This is a deterministic synthetic fixture, not customer evidence.

The review source covers seven paths at one base commit. The final candidate
contains eight paths because `src/retry-policy.ts` was added after the review.
The final patch fingerprint therefore differs from the reviewed source.

`receipt.json` is generated by the real `compareCoverage` implementation from
the built `@specport/specport` source. The generator refuses to write the
receipt unless the result is `partial`, the uncovered path is exactly
`src/retry-policy.ts`, and the next action is `review-receiver-paths`.

From the website repository:

```powershell
node scripts/generate-coverage-proof.mjs
node scripts/verify-site.mjs
```

Set `SPECPORT_SOURCE_DIR` when the SpecPort source is not available at the
default sibling path `../specport`. The source must already be built so that
`dist/core/coverage.js` and `dist/version.js` exist.

The fixture proves one bounded behavior: an uncovered path and changed review
fingerprint produce a partial coverage result. It does not prove product
correctness, security, taste, or ship readiness.
