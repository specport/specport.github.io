Agent setup

Give your agent the package and the protocol.

Install SpecPort in the project, export the two bounded playbooks, and point the agent at the same spec standard every time work changes hands.

01 / Install

Make the CLI available in the repository.

npm install --save-dev @specport/specport

Node.js 20 or newer. The install is local; source, prompts, and transcripts stay out of a SpecPort service.

02 / Export

Load the repo-to-spec and production playbooks.

npx --no-install specport skill export specport-repo-to-spec --out .codex/skills/specport-repo-to-spec
npx --no-install specport skill export specport-spec-to-production --out .codex/skills/specport-spec-to-production

Use your host’s native skill directory, such as .codex/skills or .claude/skills. Exports do not overwrite an existing directory unless you explicitly add --force.

Why and when to adopt

Add a receipt where approval happens outside the final PR gate.

Git lists changed files. CI runs checks. SpecPort adds value when a local review, agent handoff, or explicit scope was approved before the branch stopped moving.

Worth adding when

Your approval source can drift from the merge candidate.

  • A local or agent review is the approval object.
  • Work changes hands before it reaches a hosted PR.
  • You need a machine-readable, fail-closed receipt.

Probably redundant when

Your forge already requires fresh review on every final commit.

  • The final tree cannot merge after approval goes stale.
  • CODEOWNERS and branch protection cover the real risk.
  • You do not need an off-platform approval receipt.
